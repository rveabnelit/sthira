# Разработка STHIRA

Проект можно клонировать и дорабатывать локально. Ниже — всё, что нужно, чтобы поднять dev-режим,
понять структуру и не сломать критичные сценарии.

## Требования

- **Node.js 24** (обязательно: используется встроенный `node:sqlite`) — https://nodejs.org
- **pnpm 11** — `npm install -g pnpm@11` (на macOS может понадобиться `sudo`)
- Git

## Быстрый старт

```bash
git clone https://github.com/rveabnelit/sthira.git
cd sthira
cp .env.example .env          # необязательно: значения по умолчанию работают
pnpm install --frozen-lockfile
pnpm dev                      # http://localhost:3100
```

При первом запросе создаётся SQLite-база `data/sthira.db` и добавляются демо-данные
(практики, программы, ученики, платежи).

Демо-вход: `student@sthira.school / Student12345!`, админ: `admin@sthira.school / Admin12345!`.

## Скрипты

| Команда | Что делает |
|---|---|
| `pnpm dev` | dev-сервер с горячей перезагрузкой, порт 3100 |
| `pnpm build` | production-сборка (включая standalone для Docker) |
| `pnpm start` | запуск собранного приложения |
| `pnpm typecheck` | проверка TypeScript |
| `pnpm seed` | наполнить пустую базу демо-данными |
| `FORCE_SEED=true pnpm seed` | очистить и наполнить заново |
| `pnpm db:reset` | удалить файл базы |
| `pnpm test:smoke` | 22 HTTP-проверки критичных сценариев (нужен запущенный сервер) |
| `pnpm share` | временная публичная ссылка (туннель) |
| `node scripts/visual-check.mjs` | скриншоты страниц (нужен Chrome) |

## Структура

```
src/app/
  (site)/          публичные страницы: главная, практики, программы, тарифы, юридические
  (auth)/          вход, регистрация, восстановление, подтверждение email
  (app)/app/       личный кабинет: дашборд, практики, плеер, программы, прогресс, Guide
  (admin)/admin/   админка: ученики, практики, программы, платежи, база знаний, аналитика
  api/v1/          REST API
src/components/    UI-система, карточки, обложки, оболочки, формы
src/content/       стартовый контент школы (тарифы, практики, программы, база знаний)
src/lib/
  db/              схема SQLite, подключение, первичное наполнение
  auth/            пароли, сессии, токены, guard-проверки
  data/            запросы к БД и доменные преобразования
  payments/        тестовый провайдер и логика подписок
  guide.ts         поиск по базе знаний и генерация ответов
docs/              API, дизайн-система, деплой, ограничения
scripts/           seed, smoke, visual-check, share, генерация изображений
```

## Где что менять

- **Тексты и контент** — в админке (`/admin/settings`, `/admin/practices`, `/admin/programs`,
  `/admin/guide`); без кода. Стартовые значения — `src/content/catalog.ts`.
- **Дизайн** — токены и базовые классы в `src/app/globals.css`, компоненты в `src/components`.
- **Страницы и роутинг** — `src/app/**/page.tsx`.
- **API** — `src/app/api/v1/**/route.ts`; контракт описан в `docs/API.md`.
- **Бизнес-логика** — `src/lib/**`; оплата и подписки в `src/lib/payments/service.ts`.
- **Схема БД** — `src/lib/db/schema.sql` (идемпотентные `CREATE IF NOT EXISTS`; для изменений
  существующих таблиц добавляйте отдельную миграцию).
- **AI-наставник** — `src/lib/guide.ts` (локальный поиск по базе знаний; внешняя LLM подключается
  заменой генератора).

## База данных и окружение

- Файл базы: `data/sthira.db` (в git не попадает).
- Переменные: `.env.example`. Для локальной работы `.env` не обязателен.
- Демо-режим: `DEMO_MODE=true` (тестовая оплата и ссылки подтверждения), `SHOW_DEMO_HINTS=student`.
- Для «чистой» базы: `DEMO_MODE=false SEED_DEMO_DATA=false` и удалить `data/`.

## Проверки перед коммитом

```bash
pnpm typecheck
pnpm build
pnpm start            # в отдельном терминале
pnpm test:smoke
```

Smoke-тест проверяет регистрацию, доступ к платному контенту, активацию подписки только после
webhook, идемпотентность, отмену автопродления, Guide и guardrails. CI на GitHub Actions запускает
то же самое на каждый push.

## Как дорабатывать

1. Создайте ветку: `git checkout -b feature/название`.
2. Внесите изменения, прогоните проверки.
3. Коммит и push. Если нет прав на запись — сделайте **fork** и откройте pull request.
4. Прямой доступ на запись выдаётся в **Settings → Collaborators**.

## Важно

- Пароли, `.env`, `data/`, ключи и токены не коммитить.
- Оплата, email, видео и AI — провайдеры-заглушки; контракты описаны в `docs/API.md` и
  `docs/LIMITATIONS.md`. Не выдавайте демо-режим за production.
- Пользовательские данные и медицинские утверждения — только в рамках политики и законодательства.
