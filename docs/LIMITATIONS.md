# Известные ограничения MVP

Ниже — осознанные ограничения демонстрационного стенда и ближайшие шаги. Ни одно из них не влияет
на корректность оплаты, контроля доступа и сохранения прогресса.

## Платежи

- Провайдер заменён тестовым «STHIRA Pay sandbox». Подпись webhook, идемпотентность, проверка суммы
  и активация только по подтверждению реализованы полностью, но реальных списаний нет.
- Возвраты средств через API не выполняются: только через провайдера и с соответствующими правами.
- Годовая подписка, промокоды, подарочные сертификаты и смена тарифа с перерасчётом не реализованы.
- Замена тарифа выполняется как новая покупка: старый период не пересчитывается.

## Видео и плеер

- Видеопоток не подключён: используется демо-плеер с таймлайном, сохранением позиции и завершением.
  Поддерживается прямая ссылка на mp4; HLS и подписанные URL требуют настройки провайдера.
- Субтитры, качество видео и офлайн-просмотр не реализованы.
- Прогресс просмотра сохраняется для практики; для реального плеера потребуется синхронизация
  событий `timeupdate` с API (эндпоинт уже есть).

## AI-наставник

- Используется локальный retrieval-провайдер: ответы собираются из утверждённой базы знаний,
  цитируются источники, работают guardrails по медицинским вопросам. Внешняя LLM не подключена.
- Нет потоковой выдачи токенов и голосового режима.
- Дневной лимит и лимит частоты хранятся в памяти процесса: за балансировщиком нужен общий store
  (Redis).
- История диалогов хранится бессрочно до удаления аккаунта; политика хранения требует настройки.

## Инфраструктура и безопасность

- SQLite подходит для одного инстанса приложения. Для горизонтального масштабирования нужен
  PostgreSQL и общий rate-limit store.
- Ограничения частоты — в памяти процесса, сбрасываются при перезапуске.
- CSP не настроена (используются заголовки X-Frame-Options, nosniff, Referrer-Policy).
  Для production добавьте CSP с nonce для inline-скриптов Next.js.
- Email-провайдер не подключён: письма пишутся в лог, ссылки показываются в демо-режиме.
- Персистентность сессий в БД реализована; «запомнить меня» и список устройств — нет.
- Удаление аккаунта мягкое: email анонимизируется, данные профиля скрываются, платёжные документы
  сохраняются по требованиям бухучёта.

## Контент и админка

- Загрузка файлов обложек не реализована: используется URL или типографическая обложка.
  Для production нужно объектное хранилище и загрузка с проверкой типа/размера.
- Порядок уроков меняется кнопками вверх/вниз, drag-and-drop нет.
- Сохранение программы заменяет модули и уроки целиком: новые уроки получают новые идентификаторы,
  поэтому завершения привязываются к ним только после повторного прохождения. Для production нужна
  миграция структуры с сохранением идентификаторов уроков.
- Версионирование контента и предпросмотр программы глазами ученика — частично (форма предпросмотра).
- Отзывы и FAQ редактируются в коде/БД, отдельного CRUD для них нет.
- Архив практики не удаляет её из истории завершений и уроков программ — это сделано намеренно.

## Аналитика

- События пишутся в собственную таблицу; внешняя аналитика не подключена (и не блокирует работу).
- «Завершение программ» считается по уникальным урокам за период, а не по числу учеников,
  дошедших до конца.
- Демонстрационные события создаются при первичном наполнении; для production отключите seed.

## Интерфейс

- Часть состояний представлена демонстрационными данными (отзывы, расписание, метрики админки).
- Календарь занятий показывает ближайшие 14 дней, полноценный месячный календарь не реализован.
- Уведомления только внутри платформы; email/push-каналы не подключены.
- Локализация только русская.
