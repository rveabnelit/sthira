# Развёртывание, резервное копирование и восстановление

## 1. Требования

- Node.js 22+ (проверено на Node 24), pnpm 10+.
- Постоянный диск для файла SQLite (`data/sthira.db`) и каталога `public/images`.
- HTTPS на входе (reverse-proxy: Caddy, Nginx, Cloudflare и т. п.).
- Переменные окружения из `.env.example` (секреты — только в окружении, не в репозитории).

## 2. Переменные окружения production

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_APP_URL` | Публичный HTTPS-адрес (используется в письмах, sitemap, OG). |
| `NODE_ENV` | `production` |
| `DATABASE_PATH` | Абсолютный путь к файлу БД на постоянном диске. |
| `DEMO_MODE` | `false` — не показывать демо-ссылки и не создавать демо-аккаунты. |
| `SEED_DEMO_DATA` | `false` — чистая база. |
| `PAYMENT_WEBHOOK_SECRET` | Длинное случайное значение. Совпадает с настройкой провайдера. |
| `GUIDE_DAILY_LIMIT` | Дневной лимит сообщений наставнику. |
| `ALLOW_DEBUG_ENDPOINTS` | `false` — скрыть служебный GET webhook-событий. |

Первый запуск с `SEED_DEMO_DATA=false` создаёт схему и три базовых тарифа, но не создаёт учеников.
Администратора создайте отдельно (SQL или скрипт) и назначьте `role='admin'` — через публичную
регистрацию административные права не выдаются.

## 3. Сборка и запуск

```bash
pnpm install --frozen-lockfile
pnpm build
NODE_ENV=production pnpm start
```

Приложение слушает порт 3100. Reverse-proxy должен передавать заголовки `X-Forwarded-For`
и `X-Forwarded-Proto`, включить HTTPS и ограничить доступ к `/api/v1/admin` по сети при необходимости.

> **Cookie и HTTPS.** Флаг `Secure` у сессионной cookie включается, когда `NEXT_PUBLIC_APP_URL`
> начинается с `https://`. Обязательно задайте HTTPS-адрес в production: без него cookie будет
> передаваться без `Secure`. На локальном HTTP-стенде это ожидаемо и безопасно.

### systemd (пример)

```ini
[Unit]
Description=STHIRA
After=network.target

[Service]
Type=simple
WorkingDirectory=/srv/sthira
EnvironmentFile=/srv/sthira/.env
ExecStart=/usr/bin/node node_modules/next/dist/bin/next start -p 3100 -H 127.0.0.1
Restart=always
RestartSec=5
User=sthira

[Install]
WantedBy=multi-user.target
```

## 4. Резервное копирование

SQLite поддерживает горячее копирование без остановки приложения:

```bash
sqlite3 data/sthira.db ".backup '/backups/sthira-$(date +%F-%H%M).db'"
```

Альтернатива через встроенный механизм SQLite: `VACUUM INTO '/backups/sthira.db'`.
Копируйте также каталог `public/images` (пользовательские обложки, если используются).

Рекомендуемый график: ежедневно, с хранением 14 дней и проверкой целостности:

```bash
sqlite3 /backups/sthira-latest.db "PRAGMA integrity_check;"
```

## 5. Восстановление

1. Остановите приложение.
2. Сохраните текущий файл (на случай отката).
3. Замените `data/sthira.db` копией из бэкапа, удалите `sthira.db-wal` и `sthira.db-shm`, если они есть.
4. Запустите приложение и проверьте: `GET /` → 200, вход администратора, список практик, платежи.
5. Прогоните `pnpm test:smoke` (создаст тестового пользователя и тестовый платёж — в production
   используйте отдельный стенд или очистите тестовые данные после проверки).

Проверяйте восстановление не реже раза в квартал на отдельном стенде.

## 6. Мониторинг и логи

- Ошибки сервера: stdout/stderr процесса (units/логи контейнера). В коде ошибки платежей и webhook
  выводятся с префиксами `[webhook]`, `[checkout]`, `[mock-pay]`, `[guide]`.
- Проверка живости: `GET /` (200) и `GET /api/v1/plans` (200).
- Метрики продукта — в `/admin/analytics`; источник данных — таблица `analytics_events`.
- Для production подключите внешний сборщик ошибок (Sentry и т. п.) на уровне `error.tsx`,
  `global-error.tsx` и серверных обработчиков.

## 7. Миграции

Схема применяется идемпотентно при старте (`src/lib/db/schema.sql`, все объекты `IF NOT EXISTS`).
Для изменения существующих таблиц добавляйте отдельные SQL-миграции и запись в таблицу `migrations`
(образец — `schema-v1`). Перед миграцией делайте резервную копию.

## 8. Внешние сервисы перед запуском

1. **Платёжный провайдер:** заменить mock-адаптер в `src/lib/payments/` на реальный SDK/API,
   сохранить контракт `startCheckout` → webhook → активация. Проверить подпись и идемпотентность
   на тестовых платежах провайдера.
2. **Видео:** указать в практиках `video_provider='external'` и подписанные ссылки провайдера.
   Плеер уже поддерживает прямые ссылки; для HLS подключите `hls.js` и выдавайте токены с сервера.
3. **Email:** реализовать `sendEmail` в `src/lib/email.ts` через выбранный сервис, отключить `DEMO_MODE`.
4. **AI:** заменить локальный генератор на вызов модели, сохранив проверки прав, лимиты,
   фильтрацию персональных данных и guardrails; передавать только релевантные фрагменты базы знаний.
5. **Хостинг/домен:** оформить на владельца продукта, настроить HTTPS, резервные копии и мониторинг.
