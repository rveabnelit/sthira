# Постоянная ссылка на Render (бесплатно)

Render запускает Docker-образ из репозитория и даёт постоянный HTTPS-адрес вида
`https://sthira-xxxx.onrender.com`. Ссылку можно отправлять кому угодно: сервис засыпает
при простое, но **просыпается сам** при первом открытии (холодный старт 20–60 секунд).

## Шаги (один раз, ~5 минут)

1. Зарегистрируйтесь на [render.com](https://render.com) через GitHub-аккаунт `rveabnelit`.
2. **New → Blueprint** → выберите репозиторий `rveabnelit/sthira` → **Connect**.
3. Render прочитает `render.yaml` и покажет сервис `sthira` (Docker, free).
   Нажмите **Apply** / **Create**.
4. Дождитесь окончания сборки (5–10 минут). В логах будет `Ready`.
5. Откройте выданный адрес `https://…onrender.com` — это и есть постоянная ссылка.

## Что учесть

- **Бесплатный план**: сервис спит после 15 минут без запросов, но будится автоматически.
  Первый заход после сна — 20–60 секунд, дальше всё быстро.
- **База данных**: SQLite лежит внутри контейнера и **обнуляется** при перезапуске/деплое.
  Для демо это нормально: при старте снова создаётся демо-набор. Для реальных данных нужен
  платный диск Render или внешняя PostgreSQL.
- **Демо-доступ** после старта: `student@sthira.school / Student12345!` и
  `admin@sthira.school / Admin12345!` (на странице входа показывается только ученик).
- **Оплата** — тестовый провайдер, реальных списаний нет.
- Переменные окружения можно менять в Render → Environment. `NEXT_PUBLIC_APP_URL`
  не обязателен: приложение берёт `RENDER_EXTERNAL_URL` автоматически.
- Деплой обновляется автоматически при пуше в `main`.

## Альтернатива без внешних аккаунтов

VPS + Docker:

```bash
PUBLIC_URL=https://sthira.example.com docker compose up -d --build
```

Постоянный адрес, данные на диске, но нужен сервер (≈300–500 ₽/мес) и домен.
